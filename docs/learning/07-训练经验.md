# 训练经验

## 概述

强化学习训练是一个迭代试错的过程。本文档总结了 Microduck 项目中积累的训练经验，包括常见问题、解决方案和最佳实践。这些经验来自大量实验和失败，希望能帮助你避免重复踩坑。

## 奖励黑客（Reward Hacking）

### 什么是奖励黑客？

策略找到了最大化奖励的"捷径"，但没有真正学会任务。

### 常见黑客行为

#### 1. 臀部跳跃（Butt Hopping）

**现象**：机器人通过快速上下跳动来前进，而不是正常行走。

**原因**：
- 速度跟踪奖励只关心水平速度
- 没有约束垂直运动
- 跳跃比行走更容易获得高速度

**解决方案**：
```python
# 1. 添加高度稳定性奖励
height_stability = -abs(base_height - target_height)
reward += 0.5 * height_stability

# 2. 添加动作平滑惩罚
action_smoothness = -action_rate.norm()
reward += 0.01 * action_smoothness

# 3. 添加能量惩罚
energy = -action.norm()
reward += 0.001 * energy
```

#### 2. 肩滚翻（Shoulder Roll）

**现象**：机器人通过侧翻来前进，而不是行走。

**原因**：
- 只跟踪了线速度，没有约束姿态
- 翻滚时质心水平移动被误认为前进

**解决方案**：
```python
# 1. 添加强直立奖励
upright = base_orientation_z  # z 轴朝上程度
reward += 2.0 * upright

# 2. 添加角速度惩罚
angular_vel_penalty = -angular_vel.norm()
reward += 0.1 * angular_vel_penalty

# 3. 添加姿态门控
# 只有在接近直立时才给速度奖励
gate = (base_orientation_z > 0.7).float()
tracking_reward *= gate
```

#### 3. 头部三脚架（Head Tripod）

**现象**：机器人用头部支撑地面"站立"。

**原因**：
- 高度奖励没有排除异常姿态
- 头部接触地面时也能保持"高度"

**解决方案**：
```python
# 1. 添加头部接触惩罚
head_contact = contact_forces[head_body_id].norm()
reward += -0.1 * head_contact

# 2. 添加姿态门控
is_normal_pose = (
    (base_orientation_z > 0.8) & 
    (head_height > 0.1) &
    (all_feet_not_too_high)
)
height_reward *= is_normal_pose.float()

# 3. 添加异常姿态终止
if head_contact > threshold:
    terminate_episode()
```

### 防范原则

```
原则 1：用硬约束而非软惩罚
  ✗ -0.01 * tilt_angle（容易被绕过）
  ✓ 如果倾斜 > 45°，终止 episode

原则 2：组合多个奖励项
  ✗ 只用速度跟踪（容易被黑客）
  ✓ 速度 + 直立 + 平滑 + 能量（相互约束）

原则 3：监控训练过程
  ✗ 只看奖励曲线
  ✓ 定期观看视频，检查异常行为

原则 4：使用状态门控
  ✗ 在所有状态下都给奖励
  ✓ 只在正常状态下给奖励
```

## 课程学习节奏

### 问题：过早增加难度

**现象**：
- 训练初期性能上升
- 课程切换后性能突然下降
- 之后再也无法恢复

**原因**：
- 策略还没巩固基础技能
- 新挑战太复杂，策略无法同时处理
- 之前的经验被新挑战覆盖

**解决方案**：
```python
# 错误：过早增加难度
curriculum = [
    {"step": 0, "difficulty": "easy"},
    {"step": 500, "difficulty": "hard"},  # 太早！
]

# 正确：等待巩固后再增加
curriculum = [
    {"step": 0, "difficulty": "easy"},
    {"step": 2000, "difficulty": "medium"},  # 等待 2000 次迭代
    {"step": 4000, "difficulty": "hard"},    # 再等待 2000 次
]
```

### 判断时机的指标

```python
# 指标 1：奖励稳定
# 连续 500 次迭代，奖励波动 < 5%
reward_stable = (reward_std / reward_mean) < 0.05

# 指标 2：成功率
# 80% 的 episode 能达到目标
success_rate = successful_episodes / total_episodes > 0.8

# 指标 3：行为一致
# 策略表现出稳定的行为模式
behavior_consistent = check_behavior_consistency()

# 只有三个指标都满足，才进入下一阶段
if reward_stable and success_rate and behavior_consistent:
    advance_curriculum()
```

### 问题：阶段停留过久

**现象**：
- 策略在当前阶段表现完美
- 但无法泛化到更复杂的情况
- 部署到真实环境失败

**原因**：
- 策略过拟合当前阶段的特定情况
- 没有足够的变化来学习鲁棒性

**解决方案**：
```python
# 监控过拟合指标
# 1. 在验证集上测试
val_performance = evaluate_on_validation_set()

# 2. 检查行为多样性
behavior_diversity = measure_behavior_diversity()

# 如果验证性能下降或多样性不足，增加难度
if val_performance < 0.7 or behavior_diversity < threshold:
    increase_difficulty()
```

## Sim2real 差距

### 常见差距来源

#### 1. 执行器模型不准确

**现象**：
- 仿真中动作精确
- 真实机器人动作迟缓或过冲

**原因**：
- 使用了理想 PD 控制器
- 没有模拟摩擦、反电动势

**解决方案**：
```python
# 使用 BAM 执行器模型
from mjlab_microduck.actuator import BamActuatorCfg

actuator = BamActuatorCfg(
    torque_constant=0.018,
    back_emf_constant=0.018,
    resistance=1.8,
    coulomb_friction=0.08,
    viscous_friction=0.005,
)
```

#### 2. 传感器噪声

**现象**：
- 仿真中稳定
- 真实机器人抖动

**原因**：
- 仿真使用完美传感器
- 真实传感器有噪声和延迟

**解决方案**：
```python
# 添加观察噪声
OBSERVATION_NOISE = {
    "joint_pos": 0.01,      # 1% 噪声
    "joint_vel": 0.05,      # 5% 噪声
    "angular_vel": 0.05,    # 5% 噪声
    "gravity": 0.02,        # 2% 噪声
}

# 添加动作延迟
ACTION_DELAY_STEPS = 1  # 1 步延迟（20ms）
```

#### 3. 物理参数偏差

**现象**：
- 仿真中能走
- 真实机器人走不动或摔倒

**原因**：
- 质量、摩擦、CoM 等参数不准确
- 仿真和真实环境参数不一致

**解决方案**：
```python
# 域随机化
ENABLE_DOMAIN_RANDOMIZATION = True

RANDOMIZATION_RANGES = {
    "mass": (0.8, 1.2),           # ±20%
    "friction": (0.5, 1.5),       # ±50%
    "com_offset": (0.0, 0.02),    # 0-2cm
    "motor_strength": (0.9, 1.1), # ±10%
}
```

#### 4. 控制频率不匹配

**现象**：
- 仿真中稳定
- 真实机器人不稳定

**原因**：
- 仿真使用固定时间步
- 真实控制频率有抖动

**解决方案**：
```python
# 确保训练和部署使用相同频率
TRAIN_FREQUENCY = 50  # Hz
DEPLOY_FREQUENCY = 50  # Hz

# 在仿真中添加时间抖动
TIME_STEP_JITTER = 0.002  # ±2ms
```

### Sim2real 检查清单

```
□ 执行器模型：使用 BAM 而非理想 PD
□ 传感器噪声：添加观察噪声
□ 动作延迟：模拟控制延迟
□ 域随机化：随机化关键物理参数
□ 控制频率：训练和部署频率一致
□ 观察归一化：ONNX 中烘焙归一化器
□ 动作滤波：训练和部署滤波一致
□ 初始条件：随机化初始姿态
□ 地形变化：训练包含不同地形
□ 外部干扰：添加速度推力
```

## 调试技巧

### 1. Smoke Test（必做）

每次修改后，先运行 smoke test：

```bash
uv run train Mjlab-Velocity-Flat-MicroDuck \
    --env.scene.num-envs 64 \
    --agent.max_iterations 5
```

**检查项**：
- ✓ 没有 NaN 错误
- ✓ 观察维度是 61
- ✓ 动作维度是 14
- ✓ 奖励计算正常
- ✓ 环境能正常重置

### 2. 监控训练曲线

```python
# 关键指标

# 1. 总奖励（应该上升）
Episode_Reward/total

# 2. 回合长度（根据任务变化）
Episode_Length

# 3. 各项奖励（惩罚项应 ≤ 0）
Episode_Reward/tracking
Episode_Reward/upright
Episode_Reward/smoothness

# 4. 策略噪声（应逐渐下降）
Policy/mean_noise_std

# 5. 价值函数损失（应下降）
Train/value_loss
```

### 3. 定期观看视频

```bash
# 每 500 次迭代保存视频
uv run play Mjlab-Velocity-Flat-MicroDuck \
    --wandb-run-path <run> \
    --save-video \
    --video-interval 500
```

**检查项**：
- ✓ 步态自然
- ✓ 没有异常动作（跳跃、翻滚）
- ✓ 能跟踪不同速度指令
- ✓ 摔倒后能恢复（如果训练了）

### 4. 分析失败案例

```python
# 记录失败 episode 的信息

def on_episode_end(env):
    if not success:
        log_info = {
            "final_state": env.get_state(),
            "reward_breakdown": env.get_reward_breakdown(),
            "action_history": env.get_action_history(),
            "termination_reason": env.get_termination_reason(),
        }
        save_failure_log(log_info)

# 分析失败模式
failures = load_failure_logs()

print(termination_reasons)

```

### 5. A/B 测试

```python
# 比较不同配置的效果

# 配置 A：基线
config_a = {
    "reward_weights": {"tracking": 1.0, "upright": 2.0},
    "domain_randomization": False,
}

# 配置 B：添加域随机化
config_b = {
    "reward_weights": {"tracking": 1.0, "upright": 2.0},
    "domain_randomization": True,
}

# 分别训练
train(config_a, seed=42)

# 在相同测试集上评估
perf_a = evaluate(config_a, test_set)
perf_b = evaluate(config_b, test_set)

print(f"A: {perf_a:.3f}, B: {perf_b:.3f}")
```

## 超参数调优

### 学习率

```python
# 典型范围：1e-4 到 1e-3

# 太小：学习慢，可能陷入局部最优
learning_rate = 1e-4

# 太大：训练不稳定，奖励震荡
learning_rate = 1e-2

# 推荐：使用学习率调度器
lr_scheduler = {
    "type": "cosine",
    "warmup_steps": 100,
    "min_lr": 1e-5,
}
```

### PPO 裁剪参数

```python
# clip_param: 限制每次更新的幅度

# 太小：更新保守，学习慢
clip_param = 0.1

# 太大：更新激进，不稳定
clip_param = 0.3

# 推荐：0.2（默认值）
clip_param = 0.2
```

### 熵系数

```python
# entropy_coef: 鼓励探索

# 太小：过早收敛，缺乏探索
entropy_coef = 0.001

# 太大：策略随机，无法学习
entropy_coef = 0.1

# 推荐：0.01（默认值）
entropy_coef = 0.01

# 课程学习：逐步减小
entropy_schedule = [
    {"step": 0, "coef": 0.01},
    {"step": 2000, "coef": 0.005},
    {"step": 4000, "coef": 0.001},
]
```

### 并行环境数

```python
# num_envs: 影响训练速度和稳定性

# 太少：梯度估计噪声大
num_envs = 256

num_envs = 16384

# 推荐：4096（平衡速度和稳定性）
num_envs = 4096

# 24GB GPU: 4096-8192
# 16GB GPU: 2048-4096
# 12GB GPU: 1024-2048
```

## 训练失败诊断

### 问题 1：奖励一直是 NaN

**可能原因**：
1. 奖励函数有除以零
2. 观察值超出范围
3. 物理仿真不稳定

**诊断步骤**：
```python
# 1. 检查奖励函数
def check_reward_function():
    for name, func in reward_functions.items():
        try:
            value = func(env)
            if torch.isnan(value).any():
                print(f"NaN in {name}")
        except Exception as e:
            print(f"Error in {name}: {e}")

# 2. 检查观察值
def check_observations():
    obs = env.get_observations()
    if torch.isnan(obs).any():
        print("NaN in observations")
    if torch.isinf(obs).any():
        print("Inf in observations")
    if obs.abs().max() > 100:
        print(f"Large observation value: {obs.abs().max()}")

# 3. 检查物理状态
def check_physics():
    for body_id in range(num_bodies):
        pos = env.get_body_position(body_id)
        if torch.isnan(pos).any():
            print(f"NaN in body {body_id} position")
```

### 问题 2：奖励不增长

**可能原因**：
1. 学习率太小
2. 奖励信号太弱
3. 任务太难

**诊断步骤**：
```python
# 1. 检查学习率
print(f"Learning rate: {optimizer.param_groups[0]['lr']}")
# 如果 < 1e-4，尝试增大

# 2. 检查奖励幅度
reward_mean = rewards.mean()
reward_std = rewards.std()
print(f"Reward: {reward_mean:.3f} ± {reward_std:.3f}")
# 如果 std < 0.01，奖励信号太弱

# 3. 检查成功率
success_rate = successful_episodes / total_episodes
print(f"Success rate: {success_rate:.2%}")
# 如果 < 1%，任务可能太难
```

### 问题 3：训练后期性能下降

**可能原因**：
1. 课程切换过早
2. 学习率太高
3. 过拟合

**诊断步骤**：
```python
# 1. 检查课程切换时间
print(f"Curriculum switch at step {switch_step}")
print(f"Performance before: {perf_before:.3f}")
print(f"Performance after: {perf_after:.3f}")
# 如果下降 > 20%，切换过早

# 2. 检查价值函数损失
value_loss = train_metrics["value_loss"]
if value_loss increasing:
    print("Value function diverging")
    # 尝试降低学习率

# 3. 检查行为多样性
diversity = measure_behavior_diversity()
if diversity < threshold:
    print("Behavior too repetitive")
    # 增加熵系数或域随机化
```

## 最佳实践总结

### 训练前

```
□ 阅读 AGENTS.md，了解项目约定
□ 运行 smoke test，验证配置正确
□ 从简单任务开始（行走）
□ 使用默认超参数
□ 准备监控工具（W&B、视频）
```

### 训练中

```
□ 每 500 次迭代观看视频
□ 监控关键指标（奖励、长度、各项奖励）
□ 检查惩罚项是否 ≤ 0
□ 记录异常行为
□ 不要频繁修改配置
```

### 训练后

```
□ 在测试集上评估
□ 导出 ONNX 并验证
□ 在 CPU 仿真中测试
□ 部署到真实机器人
□ 记录 sim2real 差距
□ 总结经验教训
```

### 常见错误

```
✗ 一开始就训练复杂任务
✗ 频繁修改超参数
✗ 只看奖励曲线，不看视频
✗ 忽略惩罚项的符号
✗ 不做 smoke test
✗ 过早增加课程难度
✗ 忽略 sim2real 差距
```

## 总结

强化学习训练是一个迭代试错的过程，需要耐心和细心。关键要点：

1. **防范奖励黑客**：用硬约束和状态门控
2. **控制课程节奏**：等待巩固后再增加难度
3. **缩小 sim2real 差距**：使用真实执行器模型和域随机化
4. **持续监控**：定期观看视频，不要只看曲线
5. **从小开始**：先跑通简单任务，再挑战复杂任务

记住：训练失败是常态，成功是例外。每次失败都是学习的机会。
