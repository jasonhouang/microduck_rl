# 策略导出部署

## 概述

训练好的策略需要导出为 ONNX 格式，然后部署到真实机器人上运行。本文档介绍完整的导出、验证、发布和部署流程。

## 导出流程

### 1. 导出命令

```bash
# 从 wandb 运行导出
uv run scripts/export.py Mjlab-Velocity-Flat-MicroDuck \
    --wandb-run-path <entity/project/run_id> \
    --checkpoint 3000

# 输出：output.onnx
```

### 2. 导出过程

```python
# src/mjlab_microduck/export.py

def export_policy(task_id, run_path, checkpoint):
    """导出策略为 ONNX"""
    
    # 1. 加载训练好的模型
    model = load_checkpoint(run_path, checkpoint)
    
    # 2. 创建示例输入
    obs_example = torch.zeros(1, 61)  # [batch_size, obs_dim]
    
    # 3. 导出 ONNX
    torch.onnx.export(
        model.actor,
        obs_example,
        "output.onnx",
        input_names=["obs"],
        output_names=["action"],
        dynamic_axes={
            "obs": {0: "batch_size"},
            "action": {0: "batch_size"},
        },
    )
    
    # 4. 烘焙观察归一化器
    bake_normalizer("output.onnx", model.obs_normalizer)
    
    # 5. 验证输出
    validate_onnx("output.onnx")
```

### 3. 观察归一化器烘焙

**关键步骤**：观察归一化器必须烘焙到 ONNX 模型中。

```python
def bake_normalizer(onnx_path, normalizer):
    """将归一化器烘焙到 ONNX 图中"""
    
    # 加载 ONNX 模型
    model = onnx.load(onnx_path)
    
    # 创建归一化节点
    # normalized = (obs - mean) / std
    mean = normalizer.mean.cpu().numpy()
    std = normalizer.std.cpu().numpy()
    
    # 插入到图的开头
    # ...（ONNX 图操作）
    
    # 保存
    onnx.save(model, onnx_path)
```

**为什么必须烘焙？**

```python
# 训练时：
obs_normalized = (obs - mean) / std
action = policy(obs_normalized)

# 部署时（如果没烘焙）：
action = policy(obs)  # 错误！没有归一化

# 部署时（烘焙后）：
# ONNX 图内部自动归一化
action = onnx_model.run(obs)  # 正确！
```

## 验证 ONNX 模型

### 1. 结构验证

```python
def validate_onnx(onnx_path):
    """验证 ONNX 模型结构"""
    
    import onnx
    model = onnx.load(onnx_path)
    
    # 检查输入输出维度
    input_shape = model.graph.input[0].type.tensor_type.shape
    output_shape = model.graph.output[0].type.tensor_type.shape
    
    assert input_shape.dim[1].dim_value == 61, "输入必须是 61 维"
    assert output_shape.dim[1].dim_value == 14, "输出必须是 14 维"
    
    print("✓ 输入输出维度正确")
```

### 2. 数值验证

```python
def validate_numerics(onnx_path):
    """验证数值稳定性"""
    
    import onnxruntime as ort
    
    # 创建推理会话
    sess = ort.InferenceSession(onnx_path)
    
    # 测试用例
    test_cases = [
        np.zeros((1, 61), dtype=np.float32),  # 零输入
        np.random.randn(1, 61).astype(np.float32),  # 随机输入
        np.ones((1, 61), dtype=np.float32),  # 全 1 输入
    ]
    
    for i, obs in enumerate(test_cases):
        action = sess.run(None, {"obs": obs})[0]
        
        # 检查 NaN
        assert not np.isnan(action).any(), f"测试 {i} 产生 NaN"
        
        # 检查 Inf
        assert not np.isinf(action).any(), f"测试 {i} 产生 Inf"
        
        # 检查输出范围
        assert action.min() >= -10, f"测试 {i} 输出过小: {action.min()}"
        assert action.max() <= 10, f"测试 {i} 输出过大: {action.max()}"
    
    print("✓ 数值稳定性验证通过")
```

### 3. 行为验证

```python
def validate_behavior(onnx_path):
    """验证策略行为"""
    
    import onnxruntime as ort
    
    sess = ort.InferenceSession(onnx_path)
    
    # 测试 1：零观察应该产生接近零的动作
    obs_zero = np.zeros((1, 61), dtype=np.float32)
    action = sess.run(None, {"obs": obs_zero})[0]
    
    assert action.abs().max() < 0.5, "零观察应该产生小动作"
    
    # 测试 2：不同输入应该产生不同输出
    obs1 = np.random.randn(1, 61).astype(np.float32)
    obs2 = np.random.randn(1, 61).astype(np.float32)
    
    action1 = sess.run(None, {"obs": obs1})[0]
    action2 = sess.run(None, {"obs": obs2})[0]
    
    assert not np.allclose(action1, action2), "不同输入应该产生不同输出"
    
    print("✓ 行为验证通过")
```

## 机器人端部署

```bash

robotctl policy download <username>/microduck-walk
```

### 2. 加载策略

```bash
# 加载到指定槽位
robotctl policy load walk <username>/microduck-walk

# 或作为一次性动作
robotctl policy add bow <username>/microduck-bow --hold 5
```

### 3. 执行策略

```bash
# 执行策略
robotctl robot do walk

# 或执行一次性动作
robotctl robot do bow
```

### 4. 策略热切换

```python
# 运行时可以动态切换策略

# 当前：行走
policy = load_policy("walk.onnx")

# 检测到摔倒 → 切换到恢复策略
if fall_detected:
    policy = load_policy("stand.onnx")

# 恢复完成 → 切换回行走
if upright:
    policy = load_policy("walk.onnx")
```

## 策略类型

### 1. Perpetual（持续型）

```json
{
  "policy_type": "perpetual",
  "slot": "walk",
  "description": "持续运行的步态策略"
}
```

- 持续运行，直到被切换
- 用于步态（walk, stand）
- 通过 `robotctl policy load <slot> <repo>` 加载

### 2. Episodic（回合型）

```json
{
  "policy_type": "episodic",
  "duration_s": 4.0,
  "description": "持续 4 秒的动作"
}
```

- 运行固定时长后自动结束
- 用于技巧（bow, kick, roulade）
- 通过 `robotctl policy add <name> <repo>` 加载

### 3. Held Pose（保持姿态）

```json
{
  "policy_type": "perpetual",
  "unwind_s": 1.5,
  "description": "保持姿态 1.5 秒后恢复"
}
```

- 保持姿态一段时间后自动恢复
- 用于单脚站立等
- 通过 `robotctl policy add <name> <repo> --hold <seconds>` 加载

## 常见问题

### 1. 策略在仿真中正常，部署后不动

**原因**：观察归一化器未烘焙

**解决**：
```bash
# 重新导出，确保烘焙归一化器
uv run scripts/export.py --wandb-run-path <run> --checkpoint <ckpt>
```

### 2. 策略行为抖动

**原因**：观察噪声过大或动作平滑不足

**解决**：
```python
# 在部署时添加动作平滑
alpha = 0.7  # 平滑系数
action_smooth = alpha * action + (1 - alpha) * action_prev
```

### 3. 策略输出常数

**原因**：训练失败，策略陷入局部最优

**解决**：
```bash
# 检查训练曲线
# 如果奖励没有增长，重新训练

# 或尝试不同的随机种子
uv run train <task> --seed 42
```

## 总结

策略导出部署流程：

1. **导出**：使用 `scripts/export.py` 导出 ONNX
2. **验证**：检查结构、数值、行为
3. **测试**：在 CPU 仿真中测试
4. **发布**：使用 `publish` 发布到 Hub
5. **部署**：在机器人上下载、加载、执行

关键注意事项：

- **必须烘焙观察归一化器**
- **验证输出不是常数**
- **测试多策略热切换**
- **监控推理时间**
