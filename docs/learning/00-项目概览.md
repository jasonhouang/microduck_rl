# 项目概览

## 项目定位

Microduck RL 是 Microduck 双足机器人的强化学习训练环境集合。它的核心任务是：

1. **训练运动策略**：使用 PPO 算法在 MuJoCo 仿真中训练各种运动技能
2. **导出 ONNX 模型**：将训练好的策略导出为 ONNX 格式
3. **部署到真实机器人**：在 Microduck 机器人上运行这些策略

这是一个完整的 **sim2real（仿真到现实）** 项目，目标是让在仿真中训练的策略能够直接部署到真实机器人上工作。

## Sim2real 流程

```
┌─────────────────────────────────────────────────────────────┐
│  1. 仿真环境                                                 │

│     - 域随机化（增加鲁棒性）                                  │
└─────────────────────────────────────────────────────────────┘
                            ↓

│  2. 强化学习训练                                             │
│     - PPO 算法                                               │
│     - 并行环境（4096 个）                                     │
│     - 课程学习                                               │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  3. 策略导出                                                 │
│     - ONNX 格式                                              │
│     - 包含观察归一化器                                        │
│     - 验证输出范围                                            │

                            ↓

└─────────────────────────────────────────────────────────────┘
```

## 技术栈

### 核心框架

- **mjlab**：基于 MuJoCo 的强化学习训练框架
  - 提供环境管理、奖励系统、课程学习等功能
  - 支持大规模并行训练
  - GitHub: https://github.com/mujocolab/mjlab

- **MuJoCo Warp**：GPU 加速的物理引擎
  - 在 GPU 上运行物理仿真
  - 支持数千个并行环境
  - 高精度物理模拟

- **RSL RL**：强化学习算法库
  - PPO（Proximal Policy Optimization）算法
  - Actor-Critic 架构
  - 支持对称性约束

- **BAM**：执行器模型库
  - 模拟真实舵机的电压控制特性
  - 包含摩擦、反电动势等物理效应
  - GitHub: https://github.com/Rhoban/bam

### 工具链

- **uv**：Python 包管理器（替代 pip）
- **ONNX**：模型导出格式
- **Weights & Biases**：实验跟踪和可视化
- **Hugging Face Hub**：模型发布平台

## 训练环境列表

项目提供了多个预定义的训练环境，每个环境针对特定的运动技能：

| 环境名称 | 任务描述 | 难度 |
|---------|---------|------|
| `Mjlab-Velocity-Flat-MicroDuck` | 平地行走，跟踪速度指令 | ⭐⭐ |
| `Mjlab-Velocity-Rough-MicroDuck` | 粗糙地形行走 | ⭐⭐⭐ |
| `Mjlab-VelStand-Flat-MicroDuck` | 行走 + 摔倒恢复 | ⭐⭐⭐ |

### 姿态控制

| 环境名称 | 任务描述 | 难度 |
|---------|---------|------|
| `Mjlab-StandUp-Flat-MicroDuck` | 从各种姿势站起来 | ⭐⭐⭐ |
| `Mjlab-SitStand-Flat-MicroDuck` | 坐下和站起切换 | ⭐⭐⭐ |
| `Mjlab-GroundPick-Flat-MicroDuck` | 弯腰捡东西 | ⭐⭐⭐⭐ |

### 特殊动作

| 环境名称 | 任务描述 | 难度 |
|---------|---------|------|
| `Mjlab-BallKick-Flat-MicroDuck` | 踢球 | ⭐⭐⭐⭐ |
| `Mjlab-Roulade-Flat-MicroDuck` | 前滚翻 | ⭐⭐⭐⭐⭐ |

### 轮式变体

| 环境名称 | 任务描述 | 难度 |
|---------|---------|------|
| `Mjlab-Velocity-Flat-MicroDuck-Rollers` | 轮式滑行 | ⭐⭐ |
| `Mjlab-Velocity-Swizzle-MicroDuck` | 轮式旋转 | ⭐⭐⭐ |

### Backlash 变体

每个环境都有对应的 Backlash 版本（例如 `Mjlab-Velocity-Flat-Backlash-MicroDuck`），用于训练考虑齿轮间隙的策略。

## 关键文件说明

### AGENTS.md

**这是最重要的文档！** 包含了：

- 项目约定和规则
- 常见陷阱和解决方案
- 奖励设计经验
- 训练调试技巧
- Sim2real 差距处理

在开始任何工作之前，务必先阅读 AGENTS.md。

### mdp.py

所有 MDP（马尔可夫决策过程）组件的定义：

- **奖励函数**：跟踪误差、能量消耗、姿态保持等
- **观察函数**：本体感知、命令、历史动作等
- **事件函数**：域随机化、重置逻辑等
- **终止条件**：摔倒检测、超时等

### microduck_velocity_env_cfg.py

行走任务的标准配置，是其他任务的参考模板：

- 域随机化参数
- 奖励权重
- 课程学习设置
- 观察噪声配置

## 统一 Observation 契约

所有策略共享 **61 维观察空间**：

```
观察向量（61 维）
├── 本体感知（48 维）
│   ├── 角速度（3 维）
│   ├── 投影重力（3 维）
│   ├── 关节位置（14 维）
│   ├── 关节速度（14 维）
│   ├── 历史动作（14 维）
│   └── 相位变量（可选）
│
└── 控制指令（13 维）
    ├── 速度指令（3 维）：[vx, vy, ωz]
    ├── 头部姿态（4 维）：[pitch, yaw, roll, height]
    └── 身体姿态（6 维）：[x, y, z, roll, pitch, yaw]
```

这个统一接口使得：
- 不同策略可以热切换
- 运行时不需要修改接口
- 未使用的维度用零填充

## Action 空间

所有策略共享 **14 维动作空间**：

```
动作向量（14 维）
├── 左腿（5 维）
│   ├── hip_yaw
│   ├── hip_roll
│   ├── hip_pitch
│   ├── knee
│   └── ankle
│
├── 头部（4 维）
│   ├── neck_pitch
│   ├── head_pitch
│   ├── head_yaw
│   └── head_roll
│
└── 右腿（5 维）
    ├── hip_yaw
    ├── hip_roll
    ├── hip_pitch
    ├── knee
    └── ankle
```

注意：嘴部关节（mouth）不参与策略控制。

## 快速开始

### 1. 安装

```bash
git clone https://github.com/pollen-robotics/microduck_rl
cd microduck_rl

# 安装依赖（需要 CUDA）
uv sync
```

### 2. Smoke Test（5 分钟）

在开始完整训练之前，先运行 smoke test 验证配置：

```bash
uv run train Mjlab-Velocity-Flat-MicroDuck \
  --env.scene.num-envs 64 \
  --agent.max_iterations 5
```

这会在 64 个并行环境中训练 5 次迭代，快速验证：
- 环境配置正确
- 奖励函数没有 NaN
- 观察维度正确
- GPU 正常工作

### 3. 完整训练

```bash
uv run train Mjlab-Velocity-Flat-MicroDuck \
  --env.scene.num-envs 4096
```

训练过程：
- 4096 个并行环境
- 约 1-2 小时达到可用步态
- 完整训练需要 1000-6000 次迭代
- 使用 Weights & Biases 跟踪进度

### 4. 可视化

```bash
uv run play Mjlab-Velocity-Flat-MicroDuck \
  --wandb-run-path <entity/project/run_id>
```

这会启动 MuJoCo 查看器，展示训练好的策略。

### 5. 导出 ONNX

```bash
uv run scripts/export.py Mjlab-Velocity-Flat-MicroDuck \
  --wandb-run-path <entity/project/run_id>
```

导出后可以用 `scripts/infer_policy.py` 在 CPU 上测试。

### 6. 发布到 Hub

```bash
uv run publish \
  --task Mjlab-Velocity-Flat-MicroDuck \
  --wandb-run-path <entity/project/run_id> \
  --repo <username>/microduck-walk \
  --kind perpetual \
  --slot walk
```

机器人可以通过 `robotctl policy load walk <username>/microduck-walk` 下载并使用。

## 常见问题

### Q: 训练失败，奖励一直是 NaN？

A: 检查以下几点：
1. 奖励函数是否有除以零
2. 观察值是否超出合理范围
3. 初始姿态是否稳定
4. 运行 smoke test 定位问题

### Q: 策略在仿真中表现很好，但部署到机器人后失败？

A: 这是典型的 sim2real 差距，可能原因：
1. 执行器模型不够真实（检查 BAM 配置）
2. 域随机化不足（增加参数范围）
3. 观察噪声不匹配（添加传感器噪声）
4. 控制频率不一致（确保都是 50Hz）

### Q: 训练很慢怎么办？

A: 优化建议：
1. 增加并行环境数（需要更多 GPU 内存）
2. 使用更简单的任务开始
3. 减少最大迭代次数
4. 使用 Hugging Face Jobs 在云端训练

### Q: 如何创建新任务？

A: 步骤：
1. 复制 `microduck_velocity_env_cfg.py` 作为模板
2. 修改奖励函数（在 mdp.py 中添加）
3. 调整域随机化参数
4. 在 `__init__.py` 中注册新任务
5. 运行 smoke test 验证
