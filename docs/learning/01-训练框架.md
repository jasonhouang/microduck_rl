# 训练框架

## 概述

Microduck RL 基于 **mjlab**（MuJoCo Lab）框架构建，这是一个专为强化学习设计的大规模并行训练平台。核心组件包括：

- **MuJoCo Warp**：GPU 加速的物理仿真引擎
- **RSL RL**：PPO 强化学习算法实现
- **mjlab**：环境管理、奖励系统、课程学习框架

## MuJoCo Warp 并行仿真

### 核心思想

传统 MuJoCo 在 CPU 上运行单个环境。MuJoCo Warp 将仿真迁移到 GPU，同时运行数千个环境：

```
传统 MuJoCo:
  CPU → 环境1 → 物理步进 → 观察 → 动作 → 环境1
  CPU → 环境2 → 物理步进 → 观察 → 动作 → 环境2
  ...（串行，慢）

MuJoCo Warp:
  GPU → [环境1, 环境2, ..., 环境4096] → 物理步进 → 观察 → 动作
  （并行，快）
```

### 并行规模

| 环境数 | 训练速度 | GPU 内存 | 适用场景 |
|--------|---------|---------|---------|
| 64 | 慢 | 低 | Smoke test |
| 1024 | 中 | 中 | 快速实验 |
| 4096 | 快 | 高 | 正式训练 |
| 8192 | 最快 | 很高 | 大规模训练 |

### 物理精度

MuJoCo Warp 与 CPU 版 MuJoCo 使用相同的物理引擎，保证：
- 接触力计算精度一致
- 关节约束求解一致
- 摩擦模型一致

这意味着在 GPU 上训练的策略可以直接在 CPU 上推理，结果一致。

## PPO 算法

### 算法概述

PPO（Proximal Policy Optimization）是目前最流行的策略梯度算法之一：

```
PPO 核心思想：
1. 用当前策略收集一批经验数据
2. 计算优势函数（Advantage）
3. 用裁剪目标函数更新策略（限制每次更新幅度）
4. 重复
```

### 关键超参数

Microduck 使用的 PPO 配置：

```python
# 训练参数
num_steps_per_env = 24        # 每个环境收集 24 步经验
num_mini_batches = 2          # 每批数据分 2 个小批量
max_iterations = 6000         # 最大训练迭代次数
learning_rate = 1e-3          # 学习率
clip_param = 0.2              # PPO 裁剪参数
value_loss_coef = 1.0         # 价值函数损失权重
entropy_coef = 0.01           # 熵正则化权重
gamma = 0.99                  # 折扣因子
lam = 0.95                    # GAE lambda
```

### 对称性约束

Microduck 支持对称性约束（默认关闭），利用机器人的左右对称性加速训练：

```python
ENABLE_SYMMETRY = False  # 默认关闭

# 对称性约束强制：
# - 左腿动作 = 右腿动作的镜像
```


## 训练工作流

### 1. Smoke Test（必做）

每次修改配置后，先运行 smoke test：

```bash
uv run train Mjlab-Velocity-Flat-MicroDuck \
    --env.scene.num-envs 64 \
    --agent.max_iterations 5
```

Smoke test 验证：
- 环境配置正确
- 奖励函数没有 NaN
- 观察维度是 61
- 动作维度是 14
- GPU 正常工作

### 2. 短训练

Smoke test 通过后，运行短训练验证收敛性：

```bash
uv run train Mjlab-Velocity-Flat-MicroDuck \
    --env.scene.num-envs 4096 \
    --agent.max_iterations 100
```

### 3. 完整训练

短训练表现良好后，运行完整训练：

```bash
uv run train Mjlab-Velocity-Flat-MicroDuck \
    --env.scene.num-envs 4096
```

### 4. 监控训练

训练过程中通过 Weights & Biases 监控：


## NaN 防护

训练过程中，NaN 传播是最常见的问题。项目实现了多层防护：

### Patch 1: 奖励 NaN 防护

```python
# mdp.py 中的补丁
def _nan_safe_reward_compute(self, dt: float) -> torch.Tensor:
    result = _orig_reward_compute(self, dt)
    for key in self._episode_sums:
        torch.nan_to_num_(self._episode_sums[key], nan=0.0)
    return torch.nan_to_num(result, nan=0.0)
```

mjlab 在重置环境之前计算奖励，如果物理状态出现 NaN，奖励也会变成 NaN。这个补丁将 NaN 替换为 0。

### Patch 2: 优势函数 NaN 防护

```python
def _safe_compute_returns(self, obs) -> None:
    _orig_compute_returns(self, obs)
    st = self.storage
    torch.nan_to_num_(st.advantages, nan=0.0, posinf=0.0, neginf=0.0)
    torch.nan_to_num_(st.returns, nan=0.0, posinf=0.0, neginf=0.0)
```

在课程学习的突变点，价值函数可能严重偏离，导致优势函数标准化后出现极大值。这个补丁防止梯度爆炸。

### Patch 4: 被动关节过滤

```python
def _get_base_metadata_no_passive(env, run_path):
    full_names = list(robot.joint_names)
    keep_idx = [i for i, n in enumerate(full_names) if not n.startswith("passive_")]
    # ...
```

机器人模型中可能有被动关节（轮子、backlash 铰链），这些关节没有执行器。导出时过滤掉它们，保持 14 维动作空间一致。

## 总结

训练框架的核心优势：

1. **GPU 并行**：4096 个环境同时训练，大幅加速
2. **NaN 防护**：多层补丁确保训练稳定性
3. **灵活配置**：通过 Python 配置文件控制所有参数
4. **实验跟踪**：W&B 集成，方便对比和分析
5. **云端训练**：支持 HF Jobs，无需本地 GPU
